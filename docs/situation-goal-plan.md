## Inspected baseline and implementation

The baseline had Goal CRUD (multiple `active` rows allowed), initialized seven Steps, RequiredInput/RequiredInputCriterion, workflow events and Case Context. Plan/Collection were placeholders; readers selected the first active Goal. The existing real AI integration was document analysis through OpenAI Responses with `OPENAI_API_KEY` and `OPENAI_MODEL` (default `gpt-4.1-mini`); chat's deterministic mock is not a proposal provider.

- Saved Goal proposals use existing `Goal` rows with status `draft`; editing/selecting is not confirmation. A confirmed active Goal requires `confirmed_at`. Legacy active rows are not automatically promoted; multiple legacy choices require explicit selection. Confirmation archives prior active Goals, preserves historical rows, and activates only PLAN atomically. Editing an already confirmed title creates a new Goal rather than rewriting the old one; legacy CRUD cannot bypass this gate. No JournalItem or client-only record is authoritative.
- `SituationPlan` stores immutable versions: Goal ID, workflow revision, content, evidence context, `DRAFT / ACCEPTED / SUPERSEDED`, acceptance timestamp. Content contains expected output, procedure, required information and sufficiency criteria. Procedure points do not create Steps. Saving a replacement supersedes prior consent; unchanged saves do not duplicate the same version/context. Acceptance alone creates existing RequiredInput/criterion rows, linked by `plan_id`, and activates COLLECTION. Historical versions, inputs and evidence reviews are retained.
- Commands require Case/Situation scope, expected workflow revision, current source-context hash and idempotency key. SQLite's first transaction write compares/increments revision; the same transaction checks the snapshot, writes domain state, transitions Steps and appends the keyed event. Concurrent different commands cannot both win the same revision. Repeating a completed command returns current state without replaying it or another paid request. A changed request payload cannot reuse its key. A busy SQLite conflict returns 409; reload state before a new decision.
- AI work happens outside the write transaction and its snapshot is checked again before commit. Goal and Plan proposals and evidence matching use the real shared Responses transport with Zod validation, existing configuration and a 60-second timeout. Document-analysis prompt/model behavior is preserved; transport is shared. Provider failure or invalid output never confirms anything. Manual Goal, Plan and evidence-review controls remain available without AI.
- Current Situation source documents, non-rejected structured findings and active Journal knowledge form proposal context. Journal visibility checkboxes are never sent or consulted. File presence alone cannot satisfy information requirements. Source passages use strict saved-quote/range validation; a unique exact occurrence can recover display only. Nothing repairs stored offsets.
- Matching proposes values, source IDs and missing/uncertain/conflicting explanations. **AI never automatically sets SATISFIED in this MVP.** The user explicitly reviews concrete evidence/criteria. Selected conflicts, questions, claims, unverified states and unresolvable passages cannot be confirmed as sufficient. Non-conflicting inferred facts still require explicit human review. This is not semantic/legal validation or automatic resolution of contradictions elsewhere in the Case; review all relevant variants rather than selecting the latest document.
- Coverage is a read-only projection of current accepted-plan inputs. Source membership, finding/text fingerprint and verified passage are rechecked on every read. Changed/removed support makes prior sufficiency ineffective and visible as stale/Neúplné, retaining the historical value/explanation. Historical raw criterion rows can still contain their last saved status; consumers must use effective planning coverage, not treat old rows as current proof. Workflow and Case Context expose this effective coverage; superseded inputs remain history. No GET writes/backfills data.
- Manual criterion reviews store value, source snapshots and explanation; subsequent automatic matching skips explicitly reviewed criteria. Append-only WorkflowEvents retain before/after reviews, exposed in the history. Replacing Goal/Plan does not delete them. A changed source is not silently excused by an old review.
- Goal/Plan/Collection occupy the center; the left rail and right document panel remain. The Journal's former Goal editor is removed in favor of the explicit central Goal gate. Document references, colors/alignment, hover, real drag, Situation-scoped deletion and independent Journal checkboxes are retained. Successful explicit transitions refresh the rail and select the appropriate center Step. Source-change notifications hide old coverage while refreshing it. Case/Situation keys, pending refs and request versions reject stale UI continuations and double clicks. Unsaved Plan edits block AI replacement until saved; ordinary navigation itself never accepts them.

## Persistence and migration

Migration: `prisma/migrations/20261030000000_situation_goal_plan/migration.sql`.

Additive SQL adds Situation workflow revision, Goal confirmation/proposal snapshot fields, the versioned Plan table, nullable RequiredInput plan link and WorkflowEvent request key. Partial unique indexes enforce one newly confirmed active Goal and one accepted Plan per Situation; the event key is unique per Situation. Legacy active Goals do not participate in confirmed authority. Legacy input rows remain unbound historical data; this batch neither assigns them to a new Plan nor rewrites their values/statuses. Existing Steps are not backfilled or repaired.

Migration was applied only to disposable SQLite. The test first applies the three baseline migrations, seeds multiple legacy Goals, inputs/criteria and seven Steps, then applies the new migration and compares original fields and foreign keys. Fresh databases also replay all migrations in the existing regression suites. Case cascade deletion is checked. No dependency/lockfile or user DB/upload change was made.

## Limits and preservation

- AI quality, real provider connectivity/configuration, native browser geometry/accessibility and Windows runtime remain pending. No actual paid API call was made in Codex.
- Evidence review is conservative and explicit, not a general semantic resolver, legal assessment, automatic contradiction resolution or autonomous workflow controller. It does not compute legal deadlines or infer new workflow Steps.
- Snapshot validation is deliberately conservative: a changed finding/source text can require renewed review even if some words are unchanged. Historical raw evidence is preserved; effective current coverage is the authority for present support.
- This batch does not fix previous OCR/conversion/upload, literal Ctrl+C or small-viewport limits. BC-012 and BC-015 remain In Progress.
- Changed canonical mirrors 00/01/02/03/04/07/08 require later Drive synchronization; none was performed. No merge, deployment, user DB migration or Drive write is authorized here.
